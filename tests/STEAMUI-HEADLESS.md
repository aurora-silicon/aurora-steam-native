# Isolated headless session qualification

The reviewed UI71 operator packet advertised a headless option but omitted its profile writer. Both launcher layers also called physical `--select` before checking the headless profile, so a locked desktop prevented selection. This new original guard/profile pair repairs those preparation defects; it does not launch Steam, unlock a session, create a compositor or change resource/duration/capability/input gates.

The selector validates an explicit headless profile before returning the `headless` sentinel. It never queries or falls back to a physical session in that mode. Physical mode still requires the actual active local user seat to be unlocked; idle is allowed. Invalid, stale, redirected or incomplete headless profiles fail closed.

A profile must be private/user-owned and bind boot ID, compositor/Xwayland PID and start ticks, an explicit random test token inherited by the headless compositor, and that compositor's actual IPC and Wayland socket FDs. Xwayland must be its owned direct child with the exact X display argument. Wayland/IPC routing cannot point at GNOME merely because Xwayland is valid. Socket/process/profile checks are not a substitute for the operator's installed-public-binary/source and owned-unit checks.

For a separately reviewed controller operation, create a fresh mode0700 user-owned profile directory, generate a new ownership token, and pass `AURORA_HEADLESS_TOKEN` and the legitimate XDG runtime into an independently owned headless sway unit. Its exec invokes `libexec/steamui-headless-profile.py` with an absent profile path. The writer checks ownership and identity before atomically publishing mode0600 without clobber. If Xwayland is not ready it fails; the operator must diagnose that preparation and never substitute the desktop.

Repack the reviewed UI kit with the new guard installed under its existing `session-guard.py` name and this writer under `headless-profile.py`, verify every member and updated SHA256SUMS, and separately review the operator before any target stage/launch. These filenames alone do not make the old sealed packet current. Original A10/60 and C50/600,95C/1500MiB, exact source/live mapped ELF/protection/ownership/normal cleanup/restoration/frame-review gates remain required. Existing Steam must already be stopped; no foreign process, protected session, authentication state or desktop setting is modified.

CPU tests cover routing/identity/refusal policy with ordinary process metadata fixtures and real temporary Unix sockets. They grade no compositor, GUI, shader or GPU result. Real headless preparation/capture/normal teardown remain unqualified. Headless results would establish offscreen behaviour only; physical desktop/colour/performance/game and final release checks remain open.
