# Isolated headless session qualification

The reviewed UI71 operator packet advertised a headless option but omitted its profile writer. Both launcher layers also called physical `--select` before checking the headless profile, so a locked desktop prevented selection. This new original guard/profile pair repairs those preparation defects; it does not launch Steam, unlock a session, create a compositor or change resource/duration/capability/input gates.

The selector validates an explicit headless profile before returning the `headless` sentinel. It never queries or falls back to a physical session in that mode. Physical mode still requires the actual active local user seat to be unlocked; idle is allowed. Invalid, stale, redirected or incomplete headless profiles fail closed.

A profile must be private/user-owned and bind boot ID, compositor/Xwayland PID and start ticks, an explicit random test token inherited by the headless compositor, and that compositor's actual IPC and Wayland socket FDs. Xwayland must share the dedicated test unit, inherited random token and both compositor-owned X listener socket inodes, with the exact X display argument. Wayland/IPC routing cannot point at GNOME merely because Xwayland is valid. Socket/process/profile checks are not a substitute for the operator's installed-public-binary/source and owned-unit checks.

For a separately reviewed controller operation, create a fresh mode0700 user-owned profile directory, generate a new ownership token, and pass `AURORA_HEADLESS_TOKEN` and the legitimate XDG runtime into an independently owned headless sway unit. Its exec invokes `libexec/steamui-headless-profile.py` with an absent profile path. The writer checks ownership and identity before atomically publishing mode0600 without clobber. If Xwayland is not ready it fails; the operator must diagnose that preparation and never substitute the desktop.

Repack the reviewed UI kit with the new guard installed under its existing `session-guard.py` name and this writer under `headless-profile.py`, verify every member and updated SHA256SUMS, and separately review the operator before any target stage/launch. These filenames alone do not make the old sealed packet current. Original A10/60 and C50/600,95C/1500MiB, exact source/live mapped ELF/protection/ownership/normal cleanup/restoration/frame-review gates remain required. Existing Steam must already be stopped; no foreign process, protected session, authentication state or desktop setting is modified.

CPU tests cover routing/identity/refusal policy with ordinary process metadata fixtures and real temporary Unix sockets. They grade no compositor, GUI, shader or GPU result. Real headless preparation/capture/normal teardown remain unqualified. Headless results would establish offscreen behaviour only; physical desktop/colour/performance/game and final release checks remain open.

Live Linux SO_PEERCRED verifies the process reached at each socket pathname in addition to owned bound-FD evidence; unsupported systems fail closed. Profiles are opened without following symlinks and validated through the same descriptor. Publication uses one validated directory descriptor for temporary creation, nonclobber linking and cleanup. The guard is a point-in-time check: it does not hold an atomic route lease through later client connection. The reviewed operator must retain exclusive ownership of its compositor/unit and private runtime until normal cleanup; same-user tampering or endpoint replacement after validation is not prevented by this check.

Regression tests include a real second process replacing an unlinked listener while old FD/path evidence survives, symlink rejection, an opened profile surviving pathname replacement, and directory replacement during publication. These are CPU/filesystem/socket tests, not compositor or hardware qualification.

The public detached operator `libexec/steamui-detached-job.py` targets the separately sealed `full-kit71h` namespace. Only explicit `launch --headless-profile /var/tmp/steamui/headless-<16 hex>/env.json` selects headless routing. Admission validates the profile through the guard, records its content and guard source hashes in the private job receipt, and revalidates both before forwarding the profile in the clean runner environment. Invalid or changed profiles fail without physical fallback. Existing launch/status/cooperative-stop, ownership, restoration, navigation and soak rules remain intact. The prior detached operator discarded this routing environment; its old sealed packet remains historical.

Matching public wlroots0.20.2 source d783533489e1f75d6886c2ab5c5960090ef268f8 (`xwayland/server.c`) double-forks its X server, so PPID is not a reliable ownership invariant. Require `AURORA_HEADLESS_UNIT=aurora-steamui-headless-<16hex>.service` and that exact transient user unit for both processes, inherited token equality, two `-listenfd`/`-listen` socket FDs also retained by Sway and bound to the exact X display in `/proc/net/unix`. This retains routing proof for reparented Xwayland and rejects a same-display foreign process, wrong token/unit/listeners. The unit must remain exclusively owned and retained until compositor normal exit; this does not prove installed-binary source correspondence.

Use `/var/tmp/steamui/full-kit71h/headless-profile.py` in the prepared kit config, with the token and unit name inherited from the owned compositor. `xwayland force` starts the X server eagerly, but process readiness still requires an actual profile validation; startup failure never permits physical fallback.
